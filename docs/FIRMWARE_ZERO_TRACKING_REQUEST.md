# 로드셀 펌웨어 수정 요청 — 음수 영역 강제 복귀(zero-tracking) 동작

> 관련 이슈: CHAI-Student/CRK-model-HG#11 (ghost zone expected trigger).

## 1. 요약

로드셀 위 상품을 모두 제거해 측정값이 **음수 영역**에 들어가면, 펌웨어가
값을 양수로 강제 복귀시키는 동작이 관측됩니다. 물리값(음수)과 복귀값이
교대로 보고되면서 **톱니파 형태의 유령 변화 스트림**이 발생하고, 이것이
상위 판정 시스템(카메라 트리거 → 모델 정산)에 존재하지 않는 취출 이벤트로
전파됩니다. 음수 영역에서도 **부호 있는 선형 출력을 클램프 없이 그대로
보고**하도록 수정을 요청합니다.

## 2. 관측 데이터 (실기)

### 2.1 유령 변화 스트림 (빈 로드셀, 정지 상태)

시리얼 폴링 ~0.1s 간격, 연속 샘플 간 차분(delta) 기준:

| 로드셀 | delta 최소 | delta 최대 | 반복 패턴 (근사) |
|---|---|---|---|
| 0번 | 5 | 39 | — |
| 8번 | 10 | 66 | [10, 65, 52] 유사 반복 |
| 9번 | 5 | 32 | [24, 40] 유사 반복 |

- 발생 조건: **해당 셀 위 상품을 전부 제거했을 때만** 발생. 적재 상태에서는
  발생하지 않음.
- 셀마다 빈 상태에서 보고되는 절대값이 다름 (셀별 tare 오프셋 상이).
- 진폭(최대 66)이 실제 최소 상품 무게(~75g)와 겹쳐, 임계값 조정으로는
  실이벤트와 분리 불가.

### 2.2 결정 실험 — 음수 영역 톱니 확인

`MC LZ`(전체 영점) 실행 후 빈 셀에 상품을 올렸다가 제거하여 측정값을
음수 영역(−상품무게)으로 보낸 상태에서 raw 출력을 관찰한 결과, 값이
음수에 머물지 못하고 **양수 방향 점프와 음수 복귀를 반복하는 톱니파**를
확인했습니다. (raw 캡처 로그 별첨 예정)

당사 소프트웨어 스택(IO-BOARD 파이썬 서비스)은 시리얼로 수신한 6문자
문자열을 무가공 릴레이하며, 음수 처리·클램프 로직이 없음을 코드로
확인했습니다 — 즉 위 동작은 보드 펌웨어(또는 인디케이터) 계층입니다.

## 3. 추정 원인

계량 펌웨어의 zero-tracking(자동 영점 추적) 또는 음수 클램프/복귀 로직이
0 이하 값에서 동작하는 것으로 추정합니다. 판단은 담당자 확인에 맡깁니다 —
아래 요구사항은 원인 구현과 무관하게 출력 계약으로 기술했습니다.

## 4. 요구사항 (우선순위 순)

1. **[필수] 음수 영역 강제 복귀 제거** — 측정값이 음수여도 복귀·클램프
   없이 부호 있는 값을 그대로 보고. 출력 포맷은 기존 `-XXXXX`가 이미
   음수를 지원하므로 프로토콜 변경 불필요.
2. **[필수] 전 범위 선형성** — 양수/음수 영역에서 동일한 스케일·응답
   특성 유지 (하중 변화 ↔ 보고값 변화의 비례 관계가 0 경계에서 불연속
   없이 유지).
3. **[선택] zero-tracking 유지 시 밴드 제한** — 자동 영점 추적을 유지해야
   한다면 동작 밴드를 0 부근 ±수 g 이내로 제한하고, 밴드 밖(예: 취출로
   −70g 이하)에서는 절대 개입하지 않도록.
4. **[선택] 오프셋 tare** — `MC LZ` 계열로 "현재 하중을 +N g로 설정"이
   가능하면 빈 상태를 0 경계에서 떨어뜨릴 수 있어 운영이 견고해짐.

## 5. 수용 기준 (검수 절차)

1. `MC LZ`로 전체 영점 → 빈 셀 raw가 0 ± 노이즈(±2 이내)에 **정지**
   (반복 점프 없음, 10분 관찰).
2. 셀에 100g 분동 적재 → 제거: raw가 약 −100에 **안정 유지** (복귀 점프
   없음, 5분 관찰).
3. −100 상태에서 100g 재적재: raw가 0 부근으로 복귀 (선형성 확인).
4. 위 과정에서 연속 샘플 간 |delta| > 5가 물리 조작 시점 외에 발생하지
   않을 것.

## 6. 영향 범위 / 호환성

- 시리얼 프로토콜 변경 없음 (`RQ` 로드셀 응답 포맷 `±XXXXX` 그대로).
- 당사 소프트웨어는 전 구간 부호 보존으로 음수 값을 이미 정상 처리.
- 판정 로직은 절대값이 아니라 **변화량(델타)** 기반이라 영점 위치 자체에
  의존하지 않음 — 본 수정으로 상위 시스템 변경 필요 없음.
- 본 요청은 증상 우회가 아니라 **신호 품질의 근본 개선**(음수 영역 신뢰
  확보, 문 개방 시 tare 운용 가능화)이 목적입니다.

## 7. 문의

- 재현 환경/로그 제공 가능. raw 스트림은 `GET /sse?streams=loadcells&filter_method=none`
  (IO-BOARD 서비스, :8000)로 실시간 확인 가능.
